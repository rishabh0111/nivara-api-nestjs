# Tenant-local identity, with Contact as the sole ticket requester

Every identity in the model belongs to exactly one Tenant. A **User** (staff) carries `tenantId` and is invite-provisioned per Tenant, so the same real person working for two Tenants is two User rows — we chose this over a global User + Membership join so that *every* table is tenant-scoped and Postgres RLS has no cross-tenant exception, which keeps the isolation story uniform and ports cleanly to Spring Boot and FastAPI. The end customer is always a **Contact** (the requester on every Ticket); the anonymous widget visitor is a separate ephemeral **WidgetSession** that resolves to a Contact, keeping the seam to unify a person's identity across sessions deliberately open. Downstream code can therefore rely on two invariants: every row has a `tenantId`, and a Ticket's requester is always a Contact.
